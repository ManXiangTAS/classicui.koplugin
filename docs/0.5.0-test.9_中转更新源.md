# 墨页 0.5.0-test.9：中转更新源

根据用户提供的 **墨页中转技术文档(1).zip / 服务端 1.0.1 / schema 1** 对接。默认中转基础地址为：

```text
https://www.2001330.xyz/index.php?classicui_relay=
```

完整保留结尾的 `=`。检查版本请求为：

```text
https://www.2001330.xyz/index.php?classicui_relay=/v1/classicui/manifest&channel=testing
```

包下载将清单中经严格核对的 `download_path` 直接拼到完整基础地址之后，不按域名根路径拼接、不对整个基础地址再次编码。旧的 `www.2001330.xyz/classicui-updates` 不作为默认、备用或自动回退地址。

## 设置和升级

进入 **设置 → 维护与恢复 → 墨页更新 → 更新源**：

- 墨页中转（默认）：使用上方查询式入口。
- GitHub 直连：保留原官方发布检查和下载流程。
- 自定义中转地址：填写完整 HTTPS 基础地址；可用查询式入口或其他站点的路径式入口，支持 WordPress 子目录。仅接受固定的空查询前缀 `?classicui_relay=`，不接受账号、显式端口、片段或其他基础查询参数。

切换源或更新通道会清理该上下文的版本、错误和等待时间，取消运行任务；已经完整准备的更新单独保留，可以选择取消。自定义地址单独记住，切到其他源后仍可再次编辑。

自动检查和自动更新默认关闭，保留原用户已保存的开关。不会自动开启 Wi-Fi 或强制重启。正式版/测试版通道含义保持不变；全局设置搜索“中转”或“更新源”可找到墨页更新。

**首次请手动安装本版。** test.7/test.8 尚不识别此中转接口；退出 KOReader 后将安装包里的 `einkfrontend.koplugin` 覆盖到 `koreader/plugins/`，保留目录名及原设置。随后默认通过中转检查更新。

## 协议和失败处理

校验 schema、固定仓库、请求通道、状态、缓存标记、版本/标签、官方来源、文件名、整数长度、SHA-256、精确下载后缀和 KOReader 兼容修订。服务器说明作为文本展示，当前仅完整 GET，不发送条件请求或使用 ETag 缓存。

`no_release` 显示“此通道暂无发布”；`stale` 明确显示中转信息尚未刷新。503、HTML 错误页、无效 JSON、证书失败与暂无发布分开处理，保留当前安装和旧的有效暂存。

410 且错误码为 `PACKAGE_RETIRED` 时，无条件重新获取同一源、同一通道的清单，再校验版本与兼容性，最多尝试第二次下载。新的清单没有可用更新时停止；不会循环请求旧包，也不会绕回 GitHub。取消任务同时清理本任务新准备的包，包括刷新后版本变化的情况。

遵守 Retry-After 的秒数或标准 GMT 日期，后台与手动检查都避免在指定时间前重复请求。切换源后不会沿用旧源的等待时间或缓存。

中转传输只访问所选完整 BASE 下的清单和包路径，跨来源跳转及 HTTP 降级被拒绝。保留 TLS 证书链、主机名、长度和 SHA-256 校验，以及原有归档检查、逐文件清单、启动安装与中断恢复。此协议信任所选 HTTPS 中转，暂不提供独立发布签名。

客户端接口原文和 OpenAPI 见 `docs/relay/客户端接口文档.md`、`docs/relay/openapi-query.json`。协议示例与输入文档 SHA-256 留在 `tests/relay-fixtures/`。
