# 墨页更新中转：客户端接口文档

服务端插件版本：1.0.1。协议：`schema = 1`。整理日期：2026-10-23。

固定上游：`ManXiangTAS/classicui.koplugin`。本文件供 Kindle/KOReader 客户端开发对接；服务端实现不依赖任何特定客户端附加插件。

## 1. 基础地址与 URL 拼接

从 WordPress **设置 → 墨页更新中转** 复制“客户端中转基础地址”。1.0.1 默认使用不依赖伪静态的查询式入口：

```text
BASE = https://www.2001330.xyz/index.php?classicui_relay=
```

如果 WordPress 安装在 `/blog`，基础地址为 `https://example.com/blog/index.php?classicui_relay=`。客户端保存完整 BASE，保留结尾的 `=`，不得删除查询前缀。只允许这个固定的空路由查询前缀，不接受任意其他基础查询参数或片段。

已有伪静态的主机也可使用原路径式 BASE：`https://www.2001330.xyz/classicui-updates`。这种模式去掉末尾 `/`。JSON 字段、错误码和下载校验规则在两种入口完全一致。

**所有文档接口路径和 `asset.download_path` 都是拼接到完整 BASE 的逻辑后缀，不是域名根路径。**

```text
manifest_url = BASE + "/v1/classicui/manifest"
separator    = manifest_url 已含问号 ? "&" : "?"
manifest_url = manifest_url + separator + "channel=" + channel
package_url  = BASE + asset.download_path
```

示例：

```text
推荐：https://www.2001330.xyz/index.php?classicui_relay=/v1/classicui/manifest&channel=testing
存活：https://www.2001330.xyz/index.php?classicui_relay=/healthz
可选：https://www.2001330.xyz/classicui-updates/v1/classicui/manifest?channel=testing
```

不要直接使用会将前导 `/` 解释为域名根路径的通用 URL-join。不要将整个 BASE 再进行 URL 编码；下载前应验证下述严格路径格式，然后拼接。服务器也兼容旧代码直接拼接 `BASE + "/v1/classicui/manifest?channel=testing"` 的嵌套问号形式，但新开发应使用推荐的 `&channel` 形式。嵌套形式与外层参数不能重复指定 channel。

直接访问 BASE 返回 200 JSON 服务信息，包含 `base_url`、`health_url` 和 `manifest_url`。只有 health 存活不代表缓存 ready，仍需请求 manifest 验收。

## 2. 接口总览

| 方法 | BASE 后的路径 | 鉴权 | 返回 |
| --- | --- | --- | --- |
| GET / HEAD | `/v1/classicui/manifest?channel=testing` | 无 | 当前通道清单 |
| GET / HEAD | `/v1/classicui/packages/{version}/{sha256}.zip` | 无 | 完整 ZIP 或 JSON 错误 |
| GET / HEAD | `/healthz` | 无 | 服务存活 |
| POST | `/admin/sync` | Bearer 管理密钥 | 安排任务，202 |
| GET / HEAD | `/admin/status` | Bearer 管理密钥 | 同步和缓存状态 |

设备只需前两个接口。管理接口给站长/部署工具使用，管理密钥和 GitHub Token 都不应出现在设备中。

## 3. 清单请求与通道

```http
GET /classicui-updates/v1/classicui/manifest?channel=testing HTTP/1.1
Host: www.2001330.xyz
Accept: application/json
Accept-Encoding: identity
```

`channel` 必填，大小写敏感，只接受 `stable` 或 `testing`。除查询式入口必要的 `classicui_relay` 路由参数外，缺失、未知通道、数组参数或额外查询参数返回 400；不支持传入仓库、下载地址、当前版本等其他参数。上方 HTTP 报文使用可选路径式入口示意，查询式入口的完整请求地址见第 1 节。

| 通道 | 服务端选择规则 |
| --- | --- |
| stable | 非草稿、非预发布，且版本号没有 prerelease 段的最高 SemVer |
| testing | 所有非草稿正式版和测试版中的最高 SemVer |

服务端不根据客户端当前版本过滤，始终返回通道最新已就绪版本；客户端自行判断是否高于本机版本。正式版高于相同基础版本的 prerelease，数字标识符按数值比较，例如 `test.10 > test.9`，不能用普通字符串排序。无效版本号会跳过；最新有效版本的安装包损坏则记录同步失败，不悄悄以其他较旧候选替代目标。

## 4. ready 清单

下例用于说明结构：时间和说明为示例；test.8 包的字节数和摘要来自已验证的官方包。不要将示例版本硬编码到客户端。

```json
{
  "schema": 1,
  "repo": "ManXiangTAS/classicui.koplugin",
  "channel": "testing",
  "status": "ready",
  "stale": false,
  "source_checked_at": "2026-10-23T07:00:00Z",
  "release": {
    "version": "0.5.0-test.8",
    "tag": "v0.5.0-test.8",
    "prerelease": true,
    "notes": "屏保壁纸整合。",
    "page": "https://github.com/ManXiangTAS/classicui.koplugin/releases/tag/v0.5.0-test.8",
    "koreader": ["v2026.07.1", "v2026.07.2"],
    "asset": {
      "name": "ClassicUI_0.5.0-test.8_install.zip",
      "size": 1960653,
      "sha256": "f69cd3f103d67455f5b919552e1b5b6f1a32433d01b2eebf663d444cf65ff3c3",
      "origin_url": "https://github.com/ManXiangTAS/classicui.koplugin/releases/download/v0.5.0-test.8/ClassicUI_0.5.0-test.8_install.zip",
      "download_path": "/v1/classicui/packages/0.5.0-test.8/f69cd3f103d67455f5b919552e1b5b6f1a32433d01b2eebf663d444cf65ff3c3.zip"
    }
  }
}
```

| 字段 | 类型 | 含义与客户端处理 |
| --- | --- | --- |
| schema | integer | 必须为 1；遇到不兼容版本停止更新 |
| repo | string | 必须严格等于固定仓库 |
| channel | string | 必须等于本次请求通道 |
| status | string | `ready` 或 `no_release`，不能把其他值当 ready |
| stale | boolean | 正在提供上次成功缓存；可显示提示，不代表包损坏 |
| source_checked_at | string / null | UTC 最近一次完整同步成功时间；正常成功清单为 ISO 8601 字符串 |
| release | object / null | ready 为对象，no_release 为 null |
| release.version | string | 无前导 v 的 SemVer |
| release.tag | string | 原始上游标签；仅允许可解析的标签，并核对去掉单个前导 v 后等于 version |
| release.prerelease | boolean | 预发布标记，stable 不应包含预发布 |
| release.notes | string | GitHub 发布说明，可能是 Markdown、多行和 Unicode；当作文本，不执行内容 |
| release.page | string | GitHub 发布页面，仅作来源信息，更新流程不请求它 |
| release.koreader | array of string | 支持的 KOReader 修订版本；客户端核对当前版本 |
| asset.name | string | 必须为 `ClassicUI_<version>_install.zip` |
| asset.size | integer | ZIP 准确字节数，范围 1–67108864 |
| asset.sha256 | string | 64 位小写十六进制，针对 ZIP 原始字节 |
| asset.origin_url | string | GitHub 官方下载来源，仅用于核对；设备不下载此地址 |
| asset.download_path | string | 下载后缀，严格等于 `/v1/classicui/packages/<version>/<sha256>.zip` |

清单只有在文件落盘并通过全部验证后才公布 ready。GET 清单本身不触发同步、下载或修复。

服务端保证同版本、同摘要的有效下载路径返回相同原始字节。新版本准备失败时，仍在上游存在且完整的旧版本可以继续作为 ready 发布，但 `stale=true`。即使最近没有同步错误，距成功检查超过 600 秒也会标记 stale。

当前信任模型为“信任所配置的 HTTPS 中转”。SHA-256 校验不等于发布者签名；该协议暂未提供额外签名字段。

## 5. no_release 与 CACHE_NOT_READY 的区别

成功读取上游后确认该通道没有发布：HTTP 200。

```json
{
  "schema": 1,
  "repo": "ManXiangTAS/classicui.koplugin",
  "channel": "stable",
  "status": "no_release",
  "stale": false,
  "source_checked_at": "2026-10-23T07:00:00Z",
  "release": null
}
```

客户端显示“此通道暂无发布”，不下载、不清除现有安装、不回退版本。如果该 no_release 清单 stale，应同时提示信息可能尚未刷新。

首次还未同步完成、完整包缺失/损坏，或上游撤回后没有可提供的替代版本：HTTP 503，错误码 `CACHE_NOT_READY`，通常附 `Retry-After: 60`。这不是“当前已经是最新版”。

## 6. 清单缓存与 304

成功清单响应头：

```http
Content-Type: application/json; charset=utf-8
Cache-Control: public, max-age=60, must-revalidate
ETag: "<响应内容的SHA-256>"
```

首版客户端可以始终完整 GET。支持条件请求时：

1. 按 **基础地址 + 通道** 保存 ETag 和对应完整 JSON。
2. 下次带 `If-None-Match: "..."`。
3. 304 没有响应体，复用对应 JSON；不能尝试将空响应解析为 JSON。
4. 本地没有对应 JSON 时，无条件 GET 重取一次。
5. 切换域名或通道时，不混用之前缓存。

ETag 是内容摘要，不代表发布时间，也不能代替 ZIP 摘要。因 stale、时间或说明变化，版本未变时 ETag 也可能变化。

## 7. 安装包 GET / HEAD

将经严格验证的 `asset.download_path` 拼到 BASE 后下载，公开请求不带凭据。

```http
HTTP/1.1 200 OK
Content-Type: application/zip
Content-Length: 1960653
Content-Disposition: attachment; filename="ClassicUI_0.5.0-test.8_install.zip"
Cache-Control: no-store, no-transform
Accept-Ranges: none
X-Content-Type-Options: nosniff
```

- GET 从本机缓存流式输出，不将设备重定向到 GitHub。
- HEAD 成功时状态/长度与 GET 一致，不返回文件内容；可选，不要求下载前先发 HEAD。
- 不支持断点续传，Range 被忽略，返回完整 200；不要把完整响应接到旧的部分文件末尾。
- 请求可能返回 JSON 错误，先检查 HTTP 状态，再按 ZIP 处理；不要把错误 JSON 当作安装包保存后解压。
- 安装包接口除了查询式入口必要的 `classicui_relay` 路由参数，不接受其他查询参数；version 无前导 v，sha256 为小写 64 位。不要传 `%2F` 等编码路径。
- 设备请求应保留证书链和主机名校验；中转模式不应跟随跨来源或降级 HTTP 的跳转。
- 成功下载仍需比较真实字节数与 SHA-256，并复用原有 ZIP 路径检查、逐文件校验、兼容检查和安全安装/恢复流程。

服务端仅保存当前两个通道引用的包。一次 GET 已打开文件后允许传输完成；淘汰后的新请求会得到 410。客户端不能依赖固定的“旧版本宽限期”。

## 8. 错误格式与重试

错误响应一般为 `Content-Type: application/json; charset=utf-8`、`Cache-Control: no-store`：

```json
{
  "schema": 1,
  "error": {
    "code": "PACKAGE_RETIRED",
    "message": "该安装包已更新，请重新检查版本。",
    "retryable": true
  }
}
```

| HTTP | code | 客户端行为 |
| --- | --- | --- |
| 400 | INVALID_REQUEST | 修正通道、参数或路径，不自动重试 |
| 401 | UNAUTHORIZED | 管理接口密钥缺失/错误；公开接口不应要求登录 |
| 404 | NOT_FOUND | 检查 BASE/路径；若是 HTML 404，优先检查 WordPress 路由 |
| 405 | METHOD_NOT_ALLOWED | 修正方法 |
| 410 | PACKAGE_RETIRED | 重新获取同通道清单，最多重试下载一次 |
| 429 | RATE_LIMITED | 遵守 Retry-After；主要出现在管理同步接口的上游限流窗口 |
| 503 | CACHE_NOT_READY | 保留已有安装，显示暂不可用，遵守 Retry-After |
| 503 | CACHE_IO 等 | 缓存状态/存储故障，显示错误并稍后重试，站长检查后台 |

`retryable=true` 表示稍后可以再试，不代表立即无限重试。不要对 `message` 做机器匹配，按 HTTP 和 `error.code` 判断。网络中断、非 JSON 错误页、证书失败也应保留现有安装。

### 410 有界恢复流程

```text
获取/复用清单
若 no_release 或版本不高于当前版本：结束
验证元数据和兼容版本
下载到临时文件
如果返回 410 且本次还没有重试：
    丢弃临时响应
    无条件重新 GET 同一通道清单，不复用旧 ETag/JSON
    重新验证整份清单、当前版本与兼容性
    若无可用更新：结束并提示
    最多再次尝试下载一次
若第二次仍是 410 或出现其他失败：
    停止自动重试，提示稍后手动检查
若 200：
    校验长度、ZIP SHA-256 和原有包内清单
    进入现有暂存/安装/恢复流程
```

不要直接重试旧 URL，不请求 `origin_url` 绕过 410，不将尚未完整下载的版本标记为已安装。

## 9. 存活和管理接口

`GET BASE/healthz` 返回 `{"schema":1,"ok":true}`。只代表路由可执行，不代表缓存已就绪或 GitHub 可达。设备无需周期性调用。

站长可在后台设置 32–256 位的管理密钥，再调用以下接口。字符集为大小写字母、数字及 `. _ ~ -`。后台只存密钥摘要，不回显；请求头使用精确的 `Bearer <密钥>`。

```sh
BASE='https://www.2001330.xyz/index.php?classicui_relay='
curl -i -X POST "$BASE/admin/sync" -H "Authorization: Bearer $ADMIN_TOKEN"
curl -i "$BASE/admin/status" -H "Authorization: Bearer $ADMIN_TOKEN"
```

POST sync 不需要请求体。202：`{"schema":1,"status":"accepted"}`，表示已安排或复用任务，**不等于同步成功**；后续查看后台或管理 status。处在 GitHub 限流窗口时会返回 429 和等待秒数。

status 示例：

```json
{
  "schema": 1,
  "repo": "ManXiangTAS/classicui.koplugin",
  "phase": "idle",
  "queued": false,
  "source_checked_at": "2026-10-23T07:00:00Z",
  "last_attempt_at": "2026-10-23T07:00:00Z",
  "error": null,
  "retry_at": 0,
  "channels": {
    "stable": {"status":"no_release","version":null},
    "testing": {"status":"ready","version":"0.5.0-test.8"}
  },
  "cache_files": 1,
  "cache_bytes": 1960653,
  "next_scheduled_at": 1792739100
}
```

其中 `phase` 为 idle/running/failed；queued 表示存在后台请求标记。error 为 null 或 `{code,message}`。`retry_at`、`next_scheduled_at` 是 Unix 秒（后者也可为 null），其他时间是 UTC 字符串。通道未建立缓存时 status 为 `not_ready`。示例时间及 Unix 秒仅示意。

## 10. 联调检查清单

1. 启用网站插件并在后台同步，访问 testing 清单。
2. 分别测试 stable/testing；没有正式发布的 stable 返回 no_release，不能显示成网络错误。
3. 当前版本较旧时能发现更新；相同/较高版本不提示降级。
4. 下载过程仅访问完整 BASE 下的包接口，校验长度与摘要。
5. 缺失 channel 返回 400，错误 token 管理请求返回 401。
6. 缓存未就绪的 503 不被当作“已是最新版”。
7. 模拟清单取得后包被淘汰，确认 410 只触发一次清单刷新/下载重试。
8. 若实现 ETag，验证有缓存和无缓存的 304 处理。
9. 模拟网络中断、stale、包摘要错误、KOReader 不兼容；原安装和原有待恢复流程不受损。
10. 首次在实体 Kindle 上手动检查和下载，通过后再验证自动检查与自动安装。

推荐查询式入口的 OpenAPI 见 `openapi-query.json`；可选路径式入口见 `openapi.json`。网站部署和计划任务见 `网站部署与维护.md`。
