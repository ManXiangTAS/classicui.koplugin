# 0.5.0-test.4：菜单范围与其他边界复查

本轮重点检查“通用页面带出不属于当前场景的入口”、不同按钮误入相同页面、嵌套返回、旧点击区域及过期回调；同时复查手机编辑的网络边界。以下问题均已修复，证据来自真实 KOReader 桌面运行包和隔离配置。没有修改 KOReader 核心文件。

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| 菜单打开缺少统一的页面条件 | 书库菜单可被旧入口或直接调用带到设置等页面；未知菜单类型也会退化为“更多” | 显示和打开共同使用 `context.lua`；设置更多只在设置首页，书库弹层只在书库，阅读工具只在打开文档时可用；拒绝未知类型 |
| 主题“更多”与整行点击区域重叠 | 重叠约18逻辑像素，点击更多按钮边缘可能先命中套用主题 | 分开两块点击区域；分别检查按钮左边缘、中间和右边缘，确保进入管理而不套用 |
| 返回层级不正确 | 字体、主题子页按返回键统一退到只剩导航栏的 `menu`；主题管理中的“返回主题列表”实际上回到主题选择格 | 屏幕返回箭头和返回键共用父级映射，主题管理→管理列表→主题选择；字体选项→字体；根面板返回直接关闭 |
| 旧点击区域等待重绘才失效 | 切换页面或阅读页签后，排队的快速点击可能调用上一界面按钮 | 页面内容、来源、分页或位置改变时立即撤销旧区域；同一内容的状态刷新仍保留原生点击后长按语义 |
| 输入和确认回调缺少来源生命周期约束 | 页面关闭、换书或停用前端后，旧输入/确认回调仍可能操作旧上下文 | 前端创建的输入、确认和目录选择窗口归属到当前界面；切换/关闭时清理；执行前核对来源、存活状态和是否已处理；保留校验失败后的重试 |
| 收藏管理的局部搜索入口丢失 | 上版移除子页面三个点后，收藏管理、成员列表和书籍收藏选择缺少可见的局部搜索入口 | 仅这三种页面显示独立的放大镜，搜索当前内容；不显示设置首页的三个点，也不调用全局设置搜索 |
| 手机编辑的临时防火墙规则位置 | 仍以追加方式添加规则，可能排在设备原有拒绝规则之后，导致局域网连不上 | 与网页传书一致改为临时插入；端口和地址仍严格限定，失败时撤销已加规则；实际 Kindle 连通性待验收 |
| 手机编辑结束后的请求边界 | 请求入口没有独立拒绝已关闭或过期的会话，可能进入旧对象或发生空令牌拼接异常 | 在处理请求、访问布局及鉴权前返回401；不依赖下一轮轮询才能检查会话状态 |

## 菜单规则

| 页面或场景 | 可以显示的相关入口 |
|---|---|
| 设置首页 | 三个点：搜索全部设置、重启 KOReader |
| 设置分类、详情、时间与日期等 | 返回、关闭及必要的帮助；不自动带出三个点 |
| 收藏管理、收藏成员、书籍收藏选择 | 放大镜：搜索当前内容；没有设置更多 |
| 书库的书籍、作者、系列、收藏页 | 书库自己的筛选、排序和更多；管理收藏仅出现在收藏页 |
| 未打开书籍 | 不打开阅读字体/主题、目录和单书统计，不跳到一个无关设置页代替 |
| 阅读字体、排版、主题 | 三个独立功能；没有统一“更多”兼容入口或递归更多 |
| 已保存主题的管理列表 | 每个主题的更多只管理该主题，与套用操作分开 |
| 前端已停用或所属上下文已关闭 | 旧动作、弹层和回调不能重新打开前端或写入旧数据 |

页面范围验证记录见 `test-results-054/summary.json` 和 `docs/native-controls/menu-contexts.csv`。检查覆盖三种布局，包括设置首页、所有正式分类、维护子分类、收藏管理、书库和主页；阅读子页、返回和错误上下文另外通过实际窗口验证。

## 验证范围

本轮重跑基础安装/保存/重启/停用、原生菜单承接、阅读设置、主页编辑、搜索、传书和新增上下文检查。手机编辑还通过真实 Chromium、LuaSocket HTTP、分段请求与关闭清理验证。具体计数和源文件哈希见 `test-results-054/combined-summary.json`、`syntax.json`。

共760次检查通过，包含新增17类上下文与边界检查在三种布局中的51次验证；47个插件 Lua 文件通过语法检查。旧报告不会作为本轮未执行的额外检查累加。

网络测试使用127.0.0.1及临时端口；防火墙操作通过受控命令结果验证，没有实际修改主机或 Kindle 的防火墙。没有实际重启宿主。未发现这些测试覆盖范围内新增的未授权布局写入或跨页面操作；这不代表任意第三方插件已经通过安全审计。Voyage 真机、休眠、残影和实际插件组合仍需验收。

升级方法不变：完全退出 KOReader，用安装包中的 `einkfrontend.koplugin` 覆盖同名插件目录，保留原设置后启动。
