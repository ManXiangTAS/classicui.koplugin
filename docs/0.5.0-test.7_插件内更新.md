# 墨页 0.5.0-test.7：插件内更新

首次请手动安装本版。此前版本没有更新器，不能自行获得这次新增的更新功能。之后进入 **设置 → 维护与恢复 → 墨页更新** 操作，也可搜索“自动更新”或“检查更新”。

## 可选方式

| 方式 | 行为 |
| --- | --- |
| 手动检查 | 点击“检查更新”，查看可用版本与说明，再下载并准备更新 |
| 自动检查 | 默认关闭；启动/唤醒后延迟检查，使用已有网络，成功检查间隔至少 24 小时，失败至少间隔一小时再试 |
| 自动更新 | 默认关闭；开启时同时启用自动检查。发现更新后下载、校验并暂存，下次启动 KOReader 时安装 |
| 更新通道 | 正式版，或测试版与正式版。当前测试版默认使用后者 |

后台不会自动开启 Wi-Fi，不会强制重启或打断阅读。手动检查可调用 KOReader 的联网流程。关闭自动检查会同时关闭自动更新；已经准备好的更新需要单独点“取消待安装更新”撤销。

“自动更新”的安装时机是**下次启动 KOReader**。当前会话只下载并准备文件，不覆盖正在使用的代码。手动下载后可选择“重启并安装”，也可稍后正常退出并重新打开 KOReader。

中英输入、屏保、主页、传书和阅读功能保留。安装目录仍为 `einkfrontend.koplugin`，不改变现有配置位置。

## 下载与安装保护

- 只查询 `ManXiangTAS/classicui.koplugin` 的发布，匹配完整的版本安装包，不使用源代码 ZIP；支持测试版本号的数字比较，避免把 `test.10` 当成比 `test.9` 旧。
- HTTPS 检查证书链与主机名，只允许 GitHub 下载所需的明确主机，禁止降级到 HTTP 或跳往其他站点。
- 流式下载，限制超时与包大小，核对 GitHub 发布资产的 SHA-256、下载长度与包内逐文件 SHA-256 清单。
- 检查归档中的重复路径、大小写重名、越界路径、链接、异常类型、文件数量与展开大小；不直接把 ZIP 解压到运行中的插件目录。
- 在插件加载前再次校验暂存文件与 KOReader 兼容版本，备份旧文件后使用同目录的临时文件逐个替换，入口最后更新。成功后重新加载新版入口，不继续执行已编译的旧入口。
- 安装中断留下的记录会在下次启动时恢复旧文件。备份也会校验；恢复失败会停止加载插件，避免运行混合版本。桌面模拟中断不等同于断电或存储损坏的真机验证。
- 只移除旧安装清单中列出的过期文件；保留未列入清单的用户文件和独立的 KOReader 设置。
- 关闭插件、休眠或取消任务时终止更新子进程；Linux 子进程随父进程退出。重试和重新打开页面不会并行写入两个更新包。

下载包上限 64 MiB、单个展开文件 8 MiB、总展开大小 128 MiB、最多 4096 项；不支持的包会明确失败。需要为暂存和旧版本备份保留存储空间。本轮未加入镜像源、登录凭据或 GitHub Token。

## 验证与边界

使用固定版本 KOReader v2026.07.1 的真实控件、LuaSocket/LuaSec、libarchive 和文件系统测试，目标兼容版本仍是 v2026.07.1 / v2026.07.2。

验证覆盖发布筛选、版本比较、来源/摘要约束、11 份有效或异常归档、暂存与取消、旧文件和用户文件保留、安装中断恢复、空间不足、暂存篡改、非阻塞子进程、联网开关、自动检查频率、入口范围与搜索。

另外启动全新的 KOReader 进程加载完整插件树，验证安装新版、在入口替换后中断并恢复旧版、以及拒绝被篡改的暂存文件。HTTPS 测试使用本地 TLS 服务器，覆盖可信/不可信证书、主机名、允许/禁止的跳转、HTTP 降级、大小限制、完整/截断文件传输。

**当前运行环境不能直接解析 GitHub 域名，未宣称真实 GitHub 直连下载通过。** 实际 GitHub Release 元数据已通过连接器获取并验证格式。Kindle 真机的证书、网络、存储权限、耗时和断电恢复仍待验收。报告见 `test-results-057/combined-summary.json`、`tls-summary.json`、`boot-summary.json` 和 `live-network.json`；历史浏览器检查没有计入本轮。
