# Kindle 支持范围

## 项目目标

墨页面向 **KOReader 已支持并能运行目标版本的全系列 Kindle**，包含 Basic、Paperwhite、Voyage、Oasis、Scribe、Colorsoft 及较早的按键设备。Voyage 只是早期验证机，不是功能白名单。新增型号应优先沿用 KOReader 能力接口，不按外观或系列名称猜测硬件。

“全系列目标”与“所有固件、启动方式均已实测”分别记录。目前自动前光完成软件与模拟器检查，尚未收集到全系列真机验收结果。

## 功能按能力提供

| 实际硬件能力 | 亮度功能 | 色温功能 |
|---|---|---|
| 无前光 | 隐藏灯光快捷控制；设置中说明原因 | 隐藏 |
| 只有前光 | 手动调光、关灯后恢复；可扩展定时或深浅模式亮度预设 | 隐藏 |
| 前光 + 光感 | 环境光自适应、分模式记忆、个人校准 | 无暖光则隐藏 |
| 前光 + 暖光，无光感 | 手动亮度；可扩展定时或深浅模式亮度预设 | 手动色温及独立自动暖光策略 |
| 前光 + 光感 + 暖光 | 环境光自适应与亮度记忆 | 手动色温及独立自动暖光策略 |

表中的扩展项属于功能规划，不是 test.4 已实现清单。没有光感的设备无法测量环境 Lux，定时与界面模式须明确标注，不能冒充环境自适应；没有暖光硬件的设备不显示色温滑块。旧款无前光 Kindle 仍属于前端适配目标。

## 当前实现

- 自动前光通过 `hasFrontlight()`、`hasLightSensor()`、有效原生范围和可读 Lux 检测，不含 Voyage 型号白名单。Kindle 还需 KOReader 的 LIPC 前光控制就绪，并确认原生自动亮度关闭。
- 亮度原生上下限来自 Powerd，兼容不同标度与 KOReader 的合成关灯档；不固定 20、24、25 或 100 为所有 Kindle 的上限。
- 手动调光与恢复亮度适用于可控前光设备，不要求光感。无光感时前光设置页解释自动调光不可用原因，不启动采样。
- 浅色与深色界面分别存储校准和环境偏好。型号名与实际亮度范围组成配置键；换设备不直接继承启用和校准。
- 已有 KOReader 暖光功能仍可经原生设置桥接使用。本轮尚未新增墨页专用的暖光调度器或独立色温滑块；后续按 `hasNaturalLight()` 和色温 API 能力开放，亮度与色温拥有独立设置和控制权。
- 定时亮度、无光感设备的自动深浅模式亮度预设属于后续扩展；它们与 Lux 调光互斥，不能同时争抢亮度。

## 验证与兼容性边界

软件检查覆盖不同 Kindle 模型名称、光感 / 前光能力组合，以及多种原生范围，验证没有型号白名单和缺失功能时的保底。这些是模拟接口检查，不是对实际型号的实测认证。

每台真机分别记录：具体型号、固件、KOReader 版本、普通 / 无框架启动、前光和暖光范围、Lux 来源与遮挡响应、原生自动亮度状态、休眠恢复、手动覆盖及耗电。状态分为“软件已覆盖 / 接口可用待验机 / 真机已验证 / 当前接口不可用”，避免只显示一个笼统的“支持全部 Kindle”。

硬件能力参考目标 KOReader 的 [Kindle 设备实现](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/device/kindle/device.lua) 和 [前光实现](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/device/kindle/powerd.lua)。最终以运行中的设备能力和真实接口为准。
